Plan an Exit From Smoobu Dynamic Pricing

AI-assisted editorial guide · Published November 20, 2026

Smoobu’s current documentation distinguishes turning Dynamic Pricing off for a property from canceling the overall subscription. Those actions can affect retained rates differently. Before changing the system, record the prices and operating settings you want to preserve. A pricing-tool exit should not leave the team uncertain about which rates are active.

Decision processChecklistOfficial sources

Identify the active pricing source

List which properties use Smoobu Dynamic Pricing and whether another pricing tool is connected. The vendor’s guidance says competing pricing engines should not operate simultaneously. Confirm the actual configuration before making changes. Do not infer the active source merely from the most recent price you remember entering.

Record the current calendar state

Preserve an authorized record of representative future rates, manual overrides and relevant stay restrictions. Mark any blank dates. This record is a reference for checking the transition, not a recommendation for what the property should charge. Keep the date and configuration version so later differences can be explained.

Choose the intended exit action

Read the current instructions for disabling an individual property and canceling the full add-on. Smoobu describes different options for retained or restored prices. Select the action that matches the owner’s decision and confirm its effect before proceeding. Do not assume turning off automatic updates also removes the property from billing.

Assign the next pricing method

Decide who will maintain rates after the change and through which authorized tool. If a different provider will be used, coordinate the sequence using both vendors’ documentation. Keep a clear point at which the new source takes responsibility. Avoid a gap where nobody is maintaining future dates or an overlap where systems compete.

Verify rates after the change

Review the actual rate calendar and connected-channel behavior following the approved process. Smoobu notes that dates previously blank can remain blank, so check them explicitly. Investigate differences before assuming the old manual values returned. Record any additional work needed and the person responsible for it.

Use a partial-exit example

Suppose an operator stops the add-on for one property but retains it for others. Check the affected property’s rate state and billing status separately. Keep the remaining properties’ configuration unchanged unless the owner authorized a broader change. A property-level switch and an account-level cancellation should never be recorded as the same event. Keep the rate-setting handoff visible to everyone who edits availability or prices. If a staff member later turns a pricing feature back on, require a deliberate review of the expected source and affected properties. Otherwise an apparently completed exit can be reversed by a routine account change that the owner never intended.

Prepare the evidence and next action

  • Active pricing-source map
  • Dated rate and override record
  • Specific exit action selected
  • Next pricing responsibility
  • Post-change calendar and billing review
