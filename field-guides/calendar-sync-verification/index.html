Verify Imported and Exported Rental Calendars

AI-assisted editorial guide · Published November 20, 2026

Connecting two calendars does not establish that every kind of blocked date moves in both directions. Airbnb’s calendar guidance explains imports, exports and refresh behavior. An owner should document the actual connections and check how they affect availability. Calendar synchronization is an operating tool, not a guarantee that conflicting reservations cannot occur.

Decision processChecklistOfficial sources

Draw the connection direction

List each booking channel and calendar source. Record which system exports information and which imports it. A diagram with arrows is more useful than a single note saying calendars are linked. Keep calendar URLs restricted because they may reveal booking-related information, and avoid publishing them in a shared owner report or public troubleshooting screenshot.

Identify what the connection carries

Review the current official instructions for each service. Airbnb notes that some dates blocked on another calendar may not block Airbnb in the same way. Distinguish booked nights from preparation time, advance notice and owner holds. Do not assume the systems share prices, guest details or all operating rules simply because availability is connected.

Understand refresh timing

Airbnb describes periodic imports and a manual refresh option, with limits on repeated requests. Record the latest update shown for each connection when investigating a problem. Do not interpret an old timestamp as proof that the source calendar itself is wrong. The issue could be the connection, the imported information or a timing difference between systems.

Use a controlled availability check

With the owner’s authorization, choose a non-booked future date and an appropriate reversible hold to examine the intended behavior. Follow each platform’s rules and avoid creating fictitious reservations. Record the starting state, change and observed result in each system. Restore the correct availability after the check so the test does not become an unexplained long-term block.

Define who handles discrepancies

Assign one person to investigate conflicting availability and identify the source of truth for the operating team. If a real booking conflict occurs, use the relevant platform’s support process rather than assuming deletion of a calendar entry resolves the reservation. Keep reservation obligations distinct from the visual state of a calendar.

Review after replacing software

A change of manager or channel software can leave obsolete imports active. Record each connection removed or added and check the resulting availability. For example, an old management calendar and a new one may both feed the same listing. Trace the source of a block before clearing it, and retain the final connection map for the next operator. Keep a record of dates intentionally held for the owner or maintenance. If a block disappears, that record helps distinguish a synchronization problem from an authorized release of availability before the team makes another change.

Prepare the evidence and next action

  • Import/export direction map
  • Types of dates carried
  • Latest refresh observations
  • Authorized reversible test record
  • Discrepancy and software-change owner
