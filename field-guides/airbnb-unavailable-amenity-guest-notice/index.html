Notify Airbnb Guests About an Unavailable Amenity

AI-assisted editorial guide · Published November 20, 2026

Updating a listing after an amenity becomes unavailable does not automatically inform guests who already booked. Airbnb explains that guests with pending or confirmed reservations will not see those changes and directs hosts to message upcoming guests immediately when an expected amenity is removed. Build a reservation-by-reservation record so a listing edit is not mistaken for completed guest communication.

Decision processChecklistOfficial sources

Document the actual change

Identify the amenity, when availability changed and which future dates are affected based on verified information. Preserve the listing description relevant to existing reservations. Do not promise a restoration date from an unconfirmed service estimate. If the amenity raises an immediate safety issue, follow the appropriate emergency or professional response separately from this communication worksheet.

Identify affected reservations

Review upcoming bookings and pending requests against the affected date range. Assign a person to check each reservation rather than assuming a broadcast reached everyone. Record the amenity promised at booking and any guest-specific discussion. Keep the list limited to necessary booking information and restrict access to the staff handling the issue.

Send a direct, useful notice

Explain what is unavailable, the verified duration or uncertainty, and how the guest can discuss next steps. Do not bury the change in a generic welcome message. Airbnb says hosts are responsible for cancellation if guests no longer wish to keep a reservation because an expected amenity was removed. Follow the applicable process and support guidance for the specific case.

Work through an equipment example

Suppose a listed hot tub will be unavailable for several upcoming stays. Update the public listing for new shoppers and separately contact each affected existing guest. Record replies, questions and agreed actions. The operator should not assume a different amenity is an equivalent substitute or describe silence as acceptance of a reduced offering.

Track resolution and financial changes

Keep any platform-approved cancellation, alteration or refund tied to the reservation reference. Confirm the final system status instead of relying on an informal message saying it is handled. If a guest accepts the revised situation, save that communication without implying they waived rights beyond the actual agreement. Avoid promising a refund before checking the authorized process.

Confirm restoration before relisting

Use the appropriate provider’s completion evidence to verify that the amenity is available again. Update the listing and internal notes with the effective date. Check that scheduled messages no longer repeat outdated claims. Review why the issue was missed and improve the notification process, while keeping the evidence for each affected booking intact. Include a backup communication owner if the first person is away, because a published listing correction does not complete the existing-guest notification task.

Prepare the evidence and next action

  • Amenity change and verified dates
  • Original booked-description evidence
  • Affected reservation list
  • Direct notices and responses
  • Platform resolution status
  • Restoration evidence and listing update
