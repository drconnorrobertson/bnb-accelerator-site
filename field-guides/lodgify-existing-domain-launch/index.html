Connect an Existing Domain to a Lodgify Website

AI-assisted editorial guide · Published November 20, 2026

Lodgify provides instructions for linking an existing domain to its website service. The domain, email service and booking website may still be controlled by different accounts. A careful launch plan identifies those dependencies before changing DNS. This guide supports planning and vendor coordination; it does not replace the current provider-specific setup instructions.

Decision processChecklistOfficial sources

Establish who controls the domain

Identify the registrar, DNS host and authorized administrator. Confirm whether the domain is already owned by the operator and whether any transfer is actually needed. Linking a website is different from transferring domain ownership. Keep those tasks separate so a website launch does not unexpectedly become an account-recovery project.

Inventory services using the domain

Record the existing website, email and other essential services. Ask the appropriate providers which records each depends on. Do not delete unfamiliar DNS entries to simplify the screen. An apparently unrelated record may support email or another business function that the rental operation still needs.

Follow Lodgify’s current linking process

Use the official domain-linking instructions for the actual subscription and domain arrangement. The documentation distinguishes the roles of the domain host and website service. Avoid substituting a generic tutorial for the current requirements. Have the authorized administrator retain the existing configuration and record the approved changes.

Plan the change and verification window

Decide when the change should occur and who will check it. Include a way to investigate problems with the website or email without sharing credentials broadly. Do not promise instant completion merely because a DNS edit is small. Ask the providers about expected behavior and the appropriate troubleshooting steps for your setup.

Test the guest-facing workflow

After the approved change, check the intended address, secure connection and booking path using appropriate test methods. Confirm essential email still works through its provider. A homepage loading successfully does not prove that every link, form or payment integration functions. Keep the results and unresolved items with the launch record.

Prepare for a later provider change

Retain the domain account and configuration information under authorized business control. If the website service changes later, the team should know which components it controls and which require provider support. This avoids confusing an accessible website editor with ownership of the domain and all associated services. Before removing an old website service, confirm that the new configuration has passed the agreed checks and that the business retains access to the required records. Ask the relevant provider about cancellation timing. Keep the prior service available as needed under the transition plan rather than assuming that editing DNS automatically ends or transfers a subscription.

Prepare the evidence and next action

  • Domain and DNS authority
  • Dependent website and email services
  • Current Lodgify instructions
  • Approved change and rollback contacts
  • Guest-facing and email verification
